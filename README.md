# PrintCare — Printing Management System

A full-stack online printing + stationery ordering and delivery
management web app, built as a BCA final-year project.

> **Note on how this was built:** This project was generated by Claude
> in a chat/agent environment, not literally inside your VS Code. All
> files below are real and complete — copy this folder into your
> workspace (or unzip it there) and it becomes a normal, editable Flask
> project like any other.

---

## 1. Features

**Customers can:** register/login, browse printing services & stationery,
upload documents, configure prints (paper size, color, sides, copies,
binding) with a live server-calculated price, add to cart, apply
coupons, checkout with saved addresses, place orders (COD or a safe
"online payment" placeholder — no real payment gateway), track orders
on a visual timeline, view order history, manage their profile/addresses,
submit complaints, and chat with **PrintCare AI**, a database-aware
support chatbot with a local FAQ fallback.

**Admins can:** log in separately from customers, view a dashboard
(orders, revenue, customers, products), manage orders & update status,
view customers, full CRUD on printing services / stationery / categories
/ coupons, manage complaints, view revenue reports, and edit store-wide
settings (minimum order value, delivery charge, support contact info)
— all without touching code.

---

## 2. Technology Stack

- **Backend:** Python 3.12, Flask, Flask-SQLAlchemy, SQLAlchemy, Werkzeug
- **Frontend:** HTML5, CSS3, vanilla JavaScript, Jinja2 templates
- **Database:** MySQL (via PyMySQL driver)
- **Auth:** Flask sessions + Werkzeug password hashing (separate tables
  for customers and admins — customers can never become admins)
- **AI:** Pluggable AI chatbot (Anthropic-style API by default) with a
  local rule-based FAQ fallback if no API key is configured

No React/Next.js/Django/PHP/Firebase/MongoDB/Node — pure Python Flask.

## 4. Setup (Windows + VS Code + PowerShell)

### Step 1 — Check Python version
```powershell
python --version
```
You need Python 3.12. If VS Code shows a different interpreter, use
**Ctrl+Shift+P → "Python: Select Interpreter"** to pick 3.12.

### Step 2 — Create and activate a virtual environment
```powershell
python -m venv venv
venv\Scripts\activate
```

### Step 3 — Install dependencies
```powershell
pip install -r requirements.txt
```

### Step 4 — Install & configure MySQL
Install MySQL Community Server if you don't have it, then create the
database (you can use MySQL Workbench, or the command line):
```sql
CREATE DATABASE printing_management CHARACTER SET utf8mb4;
```

### Step 5 — Configure environment variables
Copy `.env.example` to `.env`:
```powershell
copy .env.example .env
```
Edit `.env` and fill in:
- `SECRET_KEY` — any long random string
- `DATABASE_URL` — e.g. `mysql+pymysql://root:yourpassword@localhost/printing_management`
- `INITIAL_ADMIN_USERNAME` / `INITIAL_ADMIN_PASSWORD` / `INITIAL_ADMIN_EMAIL` — for the admin account that seed.py will create
- `AI_API_KEY` — optional; leave blank to use the local FAQ fallback chatbot

**Never commit your real `.env` file** — it's already in `.gitignore`.

### Step 6 — Create tables and seed sample data
```powershell
python database\seed.py
```
This creates every table, inserts default settings, sample printing
services, sample stationery, two sample coupons (`WELCOME50`, `FLAT20`),
and your initial admin account. Safe to re-run — it won't duplicate data.

### Step 7 — Run the app
```powershell
python app.py
```
Open: **http://127.0.0.1:5000/**

Admin panel: **http://127.0.0.1:5000/admin/login**

## 6. Admin account safety

- The customer **registration form has no "admin" option** — customers
  can never self-elevate.
- The only way an admin account is created is via `database/seed.py`
  (reads credentials from `.env`, hashes the password with Werkzeug).
- Every `/admin/*` route is protected by the `@admin_required` decorator
  in `utils.py`.

---

## 7. AI Chatbot notes

- The chatbot ("PrintCare AI") is a floating button on every logged-in
  customer page.
- `services/chatbot_service.py` builds a small, safe context string from
  the database (current prices, settings, and — only if authenticated —
  the current user's own latest order) and sends it to the configured
  AI provider.
- The AI API key is read from `.env` on the server and is **never** sent
  to the browser.
- If `AI_API_KEY` is empty, or the AI call fails for any reason, the
  chatbot automatically falls back to a local FAQ engine that still
  reads live prices/settings from the database — so it always works,
  even fully offline.
- Chat history is stored in `chat_sessions` / `chat_messages`.

## 8. Security notes (for your viva)

- Passwords are hashed with Werkzeug (`generate_password_hash` /
  `check_password_hash`) — never stored in plain text.
- All prices, discounts, and totals are **recomputed server-side** in
  `services/pricing_service.py` — the client only sends choices
  (paper size, copies, coupon code), never numbers that are trusted.
- Uploaded files are validated by extension and saved under a random
  UUID filename via `werkzeug.utils.secure_filename`, so nothing is
  ever executed and original names/paths can't collide or be guessed.
- Customers can only ever query their own orders/addresses/documents
  (every query filters by `user_id == current_user().id`).
- Coupons are validated server-side against expiry, active flag, and
  minimum order value before any discount is applied.
- 404/500 have friendly error pages; unhandled exceptions don't leak
  stack traces to the browser.

## 10. Troubleshooting

- **`ModuleNotFoundError`** → make sure your virtual environment is
  activated (`venv\Scripts\activate`) and you ran `pip install -r requirements.txt`.
- **`sqlalchemy.exc.OperationalError` / can't connect to MySQL** →
  double-check `DATABASE_URL` in `.env`, that MySQL is running, and
  that the database `printing_management` actually exists.
- **Login works but nothing shows prices** → run `python database\seed.py`
  at least once to populate sample data.
- **Uploads fail** → the `uploads/` folder is created automatically on
  startup; make sure the app has write permission to the project folder.
- **Chatbot always uses the fallback** → check `AI_API_KEY` in `.env`;
  the fallback is expected (and totally fine) with no key configured.
- **Port already in use** → another process is using 5000; stop it or
  change the port with `app.run(debug=True, port=5001)` in `app.py`.
